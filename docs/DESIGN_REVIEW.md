# Interface and rendering review

The primary AI journey is: choose folders, describe the desired organization, request an AI plan, review destinations/reasons, select changes, organize, and use Activity for undo. Manual-rule mode retains the existing filing editor. Review opens first. An empty installation defaults to AI Hub and offers one setup action. Existing installations retain their saved rule mode. The sidebar holds navigation and monitoring status; preview/apply actions belong on Review, editing belongs on Rules, and Settings groups Folders, AI Hub, Automation and Updates/about. Save changes appears when there are edits. Organizing a selection pauses monitoring automatically and checks that the reviewed plan is current.

The dedicated window serves sustained rule editing, file comparison and recovery. A tray menu would not replace those tasks, so this change keeps one workspace with a compact pause/status area. Closing still quits after finishing current file work; it does not silently start tray-only monitoring.

The design uses one light palette: near-white canvas, white surfaces, dark ink, muted teal text, a deep teal primary action and a pale green selection. Typography and spacing are shared tokens. Extra source/size conditions and optional rename patterns are disclosed within the rule editor. Technical data-location/session details are collapsed; updates retain installed version, manual check, startup opt-out and explicit installation.

Actual rendered PNG review found and corrected inherited horizontal layout in the rules column, theme styles applied to an inactive theme, narrow preview cards, action-header overflow risk and fixed-row/path sizing. Form overflow scrolls at minimum size rather than reducing text. Real screen fixtures include a populated preview, unsaved rule/folder edits, automation opt-in, updates, history, welcome and recovery/error state.

The executable now shares one CPU rasterizer between the normal host and headless capture. Capture mode is parsed before LocalAppData access or worker startup. Thirteen screen fixtures use three finite frames each and then exit; image files and the manifest use fresh paths. PNGs show client areas with demonstration data, not OS chrome or real user-file operations. Captures cover 1160 × 820, the 960 × 680 minimum, and 125% scaling at 1200 × 850 physical pixels. The current primary/settings images are in README.

The renderer/load gate was applied by source inspection before capture. Geometry and texture updates pass through an explicit adapter to the cached software rasterizer; the Win32 host uses softbuffer GDI, waits for input/deadlines and retains hidden dirty state without constructing frames. No computer-use tool, normal native window, screenshot of the desktop or external account was used. Static visual review is complete for these client-area fixtures. Native idle/minimized/restore measurements, presentation timing, keyboard/accessibility traversal and OS interactions remain unverified; screenshots and source checks do not pass that runtime gate.

Run `FileOrganizer-v0.2.1.exe --capture ABSOLUTE_DIRECTORY [WIDTH HEIGHT [SCALE]]` in a fresh directory with a 30-second external timeout. The internal limit is 20 seconds, with no window or worker. Use the ordinary `--render-log ABSOLUTE_JSON_PATH` only during a separately authorized native diagnostic run; it records frame/wakeup and layout/raster/present totals on exit. Pair it with process-load sampling before any extended UI automation.

The AI follow-up adds confidence/reason rows and Select recommended, with no automatic selection of a fresh plan. Its settings prioritize the destination, natural-language goal and optional context/renaming; connection credentials are in a collapsed section used during setup. Progress is a static completed/total count with Cancel AI, without a continuously animating spinner. AI images are production components populated with deterministic fixture decisions, not evidence from a real model. The new client areas were inspected at 1160 × 820 and 960 × 680, including 125% at 1200 × 850. Settings scroll at narrow heights; the header cancellation action stays outside the disabled editing area.

The 0.2.0 icon repair adds original teal/cream filing-folder artwork with a transparent exterior. Checked-in ICO frames were inspected at small native sizes on light and dark backgrounds and verified byte-for-byte in the final PE. The same artwork is explicitly assigned to the native window and taskbar. Headless client-area captures show 0.2.0; they do not display or validate OS-native title bars/taskbar chrome. No native window was opened.

The 0.2.1 usability pass adds Choose beside every actual folder path and opens the native chooser directly from Add folder. Pasting remains a secondary option. Destination menus and template defaults reduce repeated entry; source-subfolder presets and KB/MB/GB controls remove common pattern/byte arithmetic. Standard and minimum-width renders show the buttons without horizontal clipping; long rule forms retain vertical scrolling. New fixtures cover empty folder setup and expanded advanced conditions. No native Windows dialog was opened; injected selection/cancellation/stale responses verify the state transitions separately from the rendered controls.
